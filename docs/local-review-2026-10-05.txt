之前修正的界面定时器和启动器改动继续保留。

本次修正
1. 无表头数据第一行丢失
   file_io.read_table 过滤可选参数时把显式 header=None 一并删掉，导致
   pandas 默认推断表头。现在保留 None，CSV/TSV/TXT/DAT 均有回归测试。

2. 工程保存误报成功
   检查 originpro.save 的 False 返回值，并核验指定路径的文件确实写入、
   非空；已有文件没有发生更新时也不算成功。补全缺省 .opju 扩展名。
   原来的 pe_save 回退仅保存 Project Explorer 文件夹，不适合充当完整
   工程另存。回退改为 save -dix，同时更新当前工程名称/路径，正确选择
   OPJ/OPJU。对无法安全放入该命令的特殊路径明确报错。

3. 导出图片改坏原图标题
   export_graph 原先调用标题清理函数，会隐藏或清空 Title/GraphTitle。
   现在按原图导出。单图和批量导出统一检查落盘文件、失败返回、回退路径
   和像素宽度；返回文件大小，避免把旧文件当作成功的新导出。

4. 不完整连接卡住 Origin 界面
   之前的 UI 定时器只保证监听时不等待，但接受连接后 readline 仍会等待
   完整一行；客户端只发半行即可占住主线程。
   嵌入式桥接现在分段、非阻塞地收发，完整请求才交给 Origin 主线程。
   每次最多执行一条直接请求和一个排队任务；慢速接收图片也不会占住 UI。
   关闭时先发送确认再清理。新增分片、空闲连接、慢读客户端、线程归属、
   队列公平性和关闭确认测试。
   当前传输上限：16 个待处理连接、单请求 32 MiB、每连接每次 64 KiB、
   30 秒无收发进展后关闭。耗时的 Origin 原生命令本身仍同步执行。

XPS/XRD 绘图器对照
仓库：https://github.com/g457337844-spec/plotter
审查版本：7f32b1acfe17450b3a582a1d38b05118e7679a28
阅读：studio/mcp_server.py、models.py、parsers.py、planning.py、origin.py、
service.py 及 tests/test_core.py。

该项目已有 12 个 MCP 工具，包含导入、选择、选项、校验、绘图、图形审核、
工作区保存/载入等。它的主要额外价值是光谱数据识别和业务流程封装。

现有通用 Origin MCP 已能直接完成：
- XPS：实测点、已有分峰、包络和背景显示；分峰填色；结合能倒序。
- XRD：多样品叠加或分层、按指定规则归一化、参考峰棒图、图层共享 X 轴。
- 原生工作簿/曲线/文字及轴标题的编辑和图形导出。

要达到 plotter 同样的一键体验，仍应复用其列角色识别、单位与缺失值检查、
PDF# 卡片文本解析、样品分组和范围检查规则，再调用 Origin MCP 执行。
通用的绘图接口本身不会可靠地推断这些科学含义。
plotter 当前的 XPS 路径绘制已有分峰数据，不等于自动完成分峰拟合和化学态指认。
演示的所有数据均为模拟数据；XRD 参考峰为人为构造，不是真实 PDF/ICDD 卡片。
