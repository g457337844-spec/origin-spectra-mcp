# Security policy

## Report a vulnerability

Please use GitHub's **private vulnerability reporting** feature for this repository if the maintainer has enabled it. If it is not enabled, request a confidential reporting channel from the maintainer without posting exploit details or credentials in public issues.

## Safety boundaries

- Never submit API keys, authentication tokens, license keys, unredacted user datasets, project backups or identifiable laboratory records.
- Sample files and logs in a report must be synthetic or sanitized.
- MCP and GUI operations interact with locally installed software; do not run untrusted scripts, arbitrary paths or third-party extensions without review.
- A successful tool or automation response is not proof that a scientific result is correct.
- Supported software versions and security fixes will be described in GitHub releases once a public release has been verified.

The current repository is under private OSS-readiness review; no public security support SLA or version policy is claimed.
